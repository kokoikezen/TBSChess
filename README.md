# TBS chess — 카탄 증강 체스

`카탄증강체스_규칙서_초안 (1).docx` (규칙서 v0.1) 와 `삼국 마석 헥스맵2 (1).html` 를 그대로 구현한
3인용 육각 전략 보드게임입니다. 한 기기에서 번갈아 두거나(핫시트), 서버를 띄워 여러 컴퓨터가 같은 판에서 둘 수 있습니다.

## 실행

### 혼자 또는 한 기기에서 (핫시트)

`index.html` 을 브라우저로 열면 됩니다. 빌드도 서버도 필요 없습니다.
세 진영을 번갈아 두는 방식이라, 차례인 사람의 자원만 화면에 펼쳐집니다.

### 다른 컴퓨터와 함께 (온라인)

한 대에서 서버를 띄우고, 나머지는 브라우저로 그 주소에 접속하면 됩니다. 설치할 것은 없습니다.

```
node server/server.js
```

띄우면 접속할 주소가 찍힙니다.

```
  이 컴퓨터     http://localhost:8080
  같은 와이파이 http://192.168.0.2:8080
```

- 먼저 접속한 세 명이 차례대로 **P1 · P2 · P3** 자리에 앉고, 네 번째부터는 **관전**이 됩니다.
- **2인전**: 위쪽 `3인전/2인전` 칸에서 **2인전**을 고르고 **다시 시작**을 누르면 방 전체가 2인전이 됩니다.
  P1(f11)·P2(a1)만 앉고 P3 본진(l1) 쪽은 빈 땅으로 남으며, P3 에 앉아 있던 사람은 관전으로 바뀝니다.
  처음부터 2인전으로 띄우려면 `PLAYERS=2 node server/server.js`. 핫시트는 `index.html?players=2`.
- 자리는 브라우저에 저장되므로 **새로고침하거나 잠시 끊겼다 돌아와도 원래 자리로** 돌아옵니다.
- 자기 차례가 아니면 판이 눌리지 않고, 다른 진영의 **자원 종류는 보이지 않습니다**(장수만 공개).
- 35초 제한은 **서버가** 셉니다. 누가 창을 닫아도 턴이 멈추지 않습니다.
- 서버를 띄운 뒤 `http://localhost:8080/?mode=hotseat` 로 열면 그 기기에서는 핫시트로 둘 수 있습니다.
- 포트를 바꾸려면 `PORT=9000 node server/server.js`.

처음 띄울 때 Windows 방화벽이 물어보면 **허용**해야 다른 컴퓨터가 접속할 수 있습니다.
같은 와이파이가 아니라 **다른 집에 있는 사람과 하려면** 터널을 하나 붙이면 됩니다.
예를 들어 `cloudflared tunnel --url http://localhost:8080` 을 실행하면 받은 주소를 그대로 공유할 수 있습니다
(Tailscale 같은 것도 같은 역할을 합니다). 인증이 없는 방이므로 주소를 아는 사람은 누구나 들어옵니다.

**판정은 언제나 서버 것이 이깁니다.** 서버가 거부하면 그 이유가 화면에 그대로 뜹니다.
남의 자원 종류는 애초에 네트워크로 나가지 않으므로, 개발자 도구를 열어도 볼 수 없습니다.

## 좌표계

열 a~l(j 제외) 11개, 행 1~11. 열 인덱스에서 `x = 열 - 5`, 그 열의 칸 수는 `11 - |x|`,
`y = 2*행 - 12 + |x|` 입니다. 큐브 좌표로 바꾸면 칸 사이 거리는 `max(|dq|,|dr|,|ds|)` 입니다.

- 변이 맞닿은 6방향: `(0,±2), (±1,±1)`
- 꼭짓점 6방향(비숍): 인접한 두 변 방향의 합 — `(±1,±3), (±2,0)`
- 나이트: `2*변방향 + 60도 꺾은 변방향` → 도착 칸 12곳
- 폰 전진 방향: 본진에서 f6 을 향하는 변 방향 — P1 `(0,-2)`, P2 `(1,1)`, P3 `(-1,1)`.
  폰의 전방 3칸은 이 방향과 그 좌우 60도 변 방향입니다.

자원 배치는 헥스맵 문서의 `DATA` 를 그대로 옮겼습니다. 테스트가 120도 회전 대칭,
본진 인접 3칸(식량9·철5·목재4), 마석의 본진 거리 4칸 이상, f6 의 숫자 7 과 거리 5·5·5 를 검증합니다.

## 구현한 규칙

규칙서 1~14장을 모두 구현했습니다.

- **준비** — 킹을 본진(f11 / a1 / l1)에 놓고, 킹 주변 2칸 안에 폰 2 + 나이트 1 을 공짜로 배치. 자원 0장.
- **턴** — ① 주사위 ② 생산 ③ 교역 ④ 이동 **또는** 소환 1회 ⑤ 종료. 제한 시간 35초(초안은 30초).
- **생산** — 나온 숫자의 점령 칸에서 1장, 그 칸에 자기 킹·퀸이 서 있으면 2장. 본진과 도둑 칸은 생산 없음.
- **7** — 8장 이상이면 절반(버림) 버리기 → 도둑 이동과 약탈 → f6 생산 순서.
- **점령** — 마지막으로 밟은 사람의 것. 이동한 칸과 소환한 칸 모두. 기물이 떠나도 유지.
- **소환** — 킹과 변이 맞닿은 6칸 중 빈칸. 퀸은 판 위 1개. 긴급 소환 +1, 17라운드부터 +1, 27라운드부터 불가.
- **이동** — 글린스키 규칙(킹만 아래 조정 참고). 캐슬링·앙파상·2칸 전진·승급 없음.
  폰은 앞 · 좌우 대각선 1칸(아래 조정 참고). 폰이 전진 방향 판 끝에 닿으면 퀸 · 룩 · 비숍 · 나이트로 승급.
- **전투** — 잡으면 자원 1장 약탈. 킹을 잡으면 그 플레이어 탈락(기물 제거, 점령 해제)하고 자원 절반을 가져감.
- **체크** — 누구의 기물이든 내 킹을 잡을 수 있으면 체크. 체크 중에는 체크를 푸는 행위만, 풀 방법이 전혀 없으면 아무 행위나.
- **승리** — 마지막 1명. 32라운드가 끝나면 점령 칸 수 → 기물 가치(폰1·나이트3·비숍3·룩5·퀸9) → 공동 승리.
- **정보** — 판·기물·점령·자원 장수는 공개, 자원 종류는 차례인 본인 화면에만.

## 초안에서 바꾼 것

플레이 중 조정한 내용입니다. 되돌리려면 아래 적힌 자리만 고치면 됩니다.

### 1. 모든 소환 비용 2배

| 기물 | 초안 | 지금 |
| --- | --- | --- |
| 폰 | 식량1 목재1 | **식량2 목재2** |
| 나이트 | 식량1 철2 | **식량2 철4** |
| 비숍 | 식량1 철1 마석1 | **목재4 철2** |
| 룩 | 목재2 철1 | **식량2 철2 마석2** |
| 퀸 | 식량1 철2 마석2 | **식량2 철4 마석4** |

### 2. 룩과 비숍의 재료 교환

비숍이 룩의 재료(목재·철)를, 룩이 비숍의 재료(식량·철·마석)를 씁니다.
**비숍은 목재만 있으면 뽑히는 싼 기물이 되고, 룩이 마석을 들고 중앙까지 나가야 하는 기물이 됩니다.**
초안 15장이 걱정한 "목재가 남고 철이 부족한" 문제와 "비숍 활용도"가 뒤집히는 조정이라,
실제로 어떻게 도는지는 아래 자가플레이 수치를 참고하세요.

### 3. 킹은 주변 한 칸만

글린스키 킹은 변 6방향 + 꼭짓점 6방향으로 12칸을 가지만, **변이 맞닿은 주변 6칸**으로 줄였습니다.
이제 킹의 이동 범위와 소환 가능 칸이 정확히 같습니다 — 킹이 움직일 수 있는 곳이 곧 기물을 놓을 수 있는 곳입니다.
판 꼭짓점인 본진(f11·a1·l1)에서는 이웃이 3칸뿐이라 특히 좁습니다.

비용표는 [js/pieces.js](js/pieces.js) 의 `COSTS`, 킹 이동은 같은 파일 `moves()` 의 `case 'K'` 에 있습니다.

### 4. 폰은 전방 3칸, 판 끝에서 승급

폰은 **앞 · 오른쪽 대각선 · 왼쪽 대각선 1칸**(전진 방향과 그 좌우 60도 칸)으로 갑니다.
세 칸 모두 빈칸이면 가고 상대 기물이 있으면 잡습니다 — 전진과 잡기를 나누지 않습니다.
전진 방향 판 끝에 닿으면 자원 2장 대신 **퀸 · 룩 · 비숍 · 나이트 중 하나로 승급**합니다.
퀸이 이미 판 위에 있으면 퀸은 고를 수 없고, 고르기 전에 시간이 다 되면 남은 것 중 가장 센 기물로 자동 승급합니다.
폰 이동은 [js/pieces.js](js/pieces.js) 의 `case 'P'`, 승급은 [js/game.js](js/game.js) 의 `choosePromotion` 에 있습니다.

### 5. 내 차례 알림 (화면 표시)

차례가 넘어오면 보드 위에 **"내 차례입니다!"** 가 크게 뜨고, 차례 카드가 내 진영 색으로 테두리를 두르며
알림음이 울립니다(온라인). 다른 탭을 보고 있어도 탭 제목에 `● 내 차례` 가 붙습니다.
**7이 나와 자원을 버려야 할 때, 도둑을 옮겨야 할 때, 폰이 승급할 때**는 붉은 알림과 깜빡이는 안내줄로 따로 알리고,
도둑을 놓을 수 있는 칸은 붉은 점선으로 깜빡입니다. 내 차례가 아니면 안내줄에 누구를 기다리는 중인지 적힙니다.

### 6. 체크 아우라 (화면 표시)

누구에게 체크를 받고 있는지 한눈에 보이도록, **체크를 거는 기물과 내 킹을 붉게 맥동하는 아우라로 감싸고
둘을 점선으로 잇습니다.** 거는 기물 아래에는 기물 이름이 붙고, 상태줄에도
`체크 (f1 P2 룩, h8 P3 나이트)` 처럼 칸·진영·기물이 적힙니다. 여러 기물에게 동시에 받는 체크도 모두 표시됩니다.
온라인에서는 내 차례가 아니어도 내 킹이 위협받고 있으면 보입니다.

## 규칙서가 정하지 않아 정한 것

초안에 적히지 않은 부분은 아래와 같이 해석했습니다. 수치나 판정을 바꾸려면 여기만 손보면 됩니다.

1. **약탈·도둑·탈락 보상의 자원 종류는 무작위**로 뽑습니다 (카탄의 도둑과 같은 방식).
   `Game.stealRandom` 한 곳에 모여 있습니다.
2. **킹은 공격받는 칸으로 들어갈 수 없습니다.** 다른 기물이 움직여 내 킹이 드러나는 수는
   체크 중이 아니면 막지 않습니다 — 3인 게임에서는 자진해서 위험을 지는 선택도 전술이기 때문입니다.
3. **제한 시간 35초는 턴 전체**에 걸립니다. 굴리지 않은 채 시간이 지나면 자동으로 굴려 생산만 처리하고
   턴을 넘깁니다. 버리기와 도둑 처리 중에는 시계를 멈춥니다(여러 사람이 관여하므로).
4. **플레이어 간 교역은 제안 → 수락/거절** 한 번으로 성립합니다. 흥정을 주고받는 단계는 두지 않았습니다.
5. **폰 승급은 판 끝 칸에 도착하는 즉시** 일어나고, 기물을 고를 때까지 턴이 넘어가지 않습니다.
   밟은 칸의 점령은 그대로 남습니다.
6. **추가 비용(긴급 소환·전쟁 피로)으로 낼 자원은 플레이어가 고릅니다.** "아무 자원"이므로 선택지로 뒀습니다.
7. **32라운드 판정은 생존자끼리** 비교합니다.

## 테스트해 볼 점 (규칙서 15장)

무작위로 두는 봇으로 자동 플레이한 결과입니다. 봇이 공격을 설계하지 못하므로 절대값보다
**비용을 바꿨을 때 어느 쪽으로 움직이는지**를 보는 용도로 쓰세요.

| | 초안 비용 | 2배 + 룩·비숍 교환 |
| --- | --- | --- |
| 32라운드까지 간 판 | 97% | **100%** |
| 킹 사살로 끝난 판 | 3% | **0%** |
| 판당 소환 | 약 25회 | **18.4회** |
| 끝날 때 남은 자원 | — | **3인 합계 66장** |
| 소환된 기물 | — | **폰 54% · 나이트 21% · 비숍 20% · 룩 4% · 퀸 0%** |

- 비용이 2배가 되면서 **기물이 적게 깔리고 킹까지 닿는 일이 거의 없어졌습니다.** 32라운드 점령 판정이 사실상 기본 결말입니다.
- **룩 4% · 퀸 0%** 는 둘 다 마석을 요구하는데 마석이 13칸뿐이고 본진에서 4칸 이상 떨어져 있기 때문입니다.
  반대로 목재만 쓰는 **비숍은 20%** 로 흔해졌습니다.
- 자원이 66장이나 남는 것은 살 수 있는 것이 마땅치 않아 쌓이기 때문입니다. 7이 나올 때 버리기가 자주 걸립니다.
